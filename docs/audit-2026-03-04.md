### Service Layer Architecture

```
Components (client)
  -> API Routes (/api/*)
    -> Services (services/indicators.js, services/dashboard-stats.js)
      -> Supabase (lib/supabase-server.js)
        -> Tables: indicators, indicator_values, news_items, news_runs, news_errors, data_change_log
    -> External APIs (BNM XML, Open-Meteo JSON, Telegram Bot)
  -> Static JSON (data/charts/*.json) for SSG chart pages
```

### Supabase Tables

| Table | Purpose |
|-------|---------|
| `indicators` | Indicator metadata (name, unit, slug, frequency, source) |
| `indicator_values` | Time series (indicator_id, year, value) — composite unique on (indicator_id, year) |
| `news_items` | News articles (title, summary, url, source_slug, published_at, impact_score, duplicate_group) |
| `news_runs` | News pipeline execution logs |
| `news_errors` | News fetch/processing errors |
| `data_change_log` | Full audit trail for all data mutations |

### Data Flow: Indicator from Source to Chart

```
StatBank PxWeb API
  | (cron 03:00 UTC daily)
  v
/api/cron/sync-statbank
  | fetchTable() -> parseJsonStat2()
  | 1 req/s rate limit + exponential backoff
  v
Supabase: indicators (upsert metadata)
Supabase: indicator_values (upsert year/value rows)
Supabase: data_change_log (audit entry)
  |
  v
scripts/generate-statbank-charts.mjs
  | reads Supabase -> writes data/charts/statbank-*.json
  v
Next.js build (SSG)
  | reads data/charts/*.json
  | generateStaticParams -> pre-renders /chart/[id]
  v
Browser: /chart/statbank-gdp
  | static HTML + JSON inlined
  v
ChartCanvas -> engine.js -> <canvas> render
  | + sr-only data table
  | + ShareButtons (Telegram, WhatsApp, GIF, PDF)
  v
User sees animated chart with tooltip interaction
```
