# adevar.ai

Economic data dashboard for the Republic of Moldova. Independent monitoring of macroeconomic and energy indicators from official sources (BNS, ANRE, BNM).

## Stack

- **Framework**: Next.js 15 (App Router, JavaScript — no TypeScript)
- **Database**: Supabase (PostgreSQL)
- **Charts**: Custom canvas rendering engine (`lib/engine.js`)
- **Styling**: Single `app/globals.css`, CSS custom properties for theming
- **Font**: Onest (Google Fonts)
- **Deploy**: Vercel Pro, auto-deploy from `main`

## Key Files

| Path | Purpose |
|------|---------|
| `lib/charts.js` | Chart registry (CHARTS array) and data loaders |
| `lib/engine.js` | Canvas chart rendering engine |
| `data/charts/*.json` | Static chart data files |
| `data/statbank-indicators.json` | StatBank indicator mappings |
| `lib/statbank.js` | StatBank PxWeb API client |
| `scripts/sync-statbank.mjs` | Daily data sync script |
| `app/globals.css` | All styles (single file) |
| `contexts/LangContext.js` | i18n provider (RO/EN/RU) |
| `contexts/ThemeContext.js` | Theme provider (light/dark) |
| `lib/i18n.js` | Translation strings |

## Data Pipeline

- StatBank PxWeb API syncs daily at **03:00 UTC** via Vercel cron (`vercel.json`)
- Rate limit StatBank requests to **1 req/s** — the API will block faster rates
- Supabase has a **frequency check constraint** on indicator rows: valid values are `yearly`, `monthly`, `quarterly`

## Rules

- **Three languages**: All user-facing text must support RO, EN, and RU via `t()` from `useLang()`
- **Build before committing**: Always run `npm run build` and verify it passes before committing
- **Never modify existing chart JSONs** in `data/charts/` — they are generated by sync scripts
- **Commit style**: `type(scope): description` — types: `fix`, `feat`, `chore`, `ci`, `docs`, `refactor`, `security`
- **No TypeScript**: This is a JavaScript project. Do not add `.ts`/`.tsx` files
- **Prefer editing over creating**: Edit existing files rather than creating new ones when possible

## Gotchas

- Chart pages use `export const dynamic = 'force-static'` (SSG) — they are statically generated at build time
- `ShareButtons` component uses `position: absolute` — its parent must have `position: relative` or buttons will be invisible (clipped by `overflow: hidden` on `.main-content`)
- `ChartCanvas` is dynamically imported with `ssr: false` — canvas code cannot run server-side
- The `ComingSoon` component renders when `chart.soon` is truthy or `chartData` is null
- API routes use server-side Supabase client from `lib/supabase-server.js` — never import the browser client in API routes
